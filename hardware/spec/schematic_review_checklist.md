# Rev A schematic review checklist (M4)

Use this as the structured design review the plan promises in M4. Every box needs a reviewer initial and evidence (sheet/net, datasheet page). Items tagged with a TO-VERIFY ID must be closed in `to_verify.yaml` before the review can pass.

## A. Power tree and sequencing
- [ ] Every rail in `rails.yaml` exists in the schematic with the same name, regulator refdes, enable net and JP/TP.
- [ ] 3V3_AON regulator holds ≥ 3.0 V at the C6 under a 382 mA TX burst down to the chosen battery cutoff (TPS62840 100 % mode) TO-VERIFY[TV-18]; decide TPS62840 vs TPS63900.
- [ ] VDDCORE regulator meets AN6000: 2 A, 30 mVpp ripple, ±35 mV transient, 0.61 → 0.782 V within 200 µs, slew ≥ 0.86 V/ms, active discharge, DVFS via Q1 TO-VERIFY[TV-19].
- [ ] Q1 meets AN6000 (IDSS ≪ 2 µA, VGS(th) < 1.8 V, Crss < 20 pF).
- [ ] VDDCORE_EN = PWR_ON AND CTX_CORE_EN (U26) drives U15, U17 and U18 EN; U26 powered from 3V3_AON; inputs have pull-downs.
- [ ] VDD (3V3_CTX) and VDDA1V8_AON are enabled from SYS_CTX, not from PWR_ON.
- [ ] Sequencing chapter of AN5967 read and reflected (VDDA18PMU, VDDSMPS, VDDA18CSI, VDDA18USB, XSPI port supplies) TO-VERIFY[TV-12].
- [ ] POPL value set in firmware > VDDCORE discharge time; PWR_ON behaviour under NRST known TO-VERIFY[TV-13].
- [ ] Internal SMPS pins (VDDSMPS, VLXSMPS, etc.) connected for the external-SMPS (bypass) configuration as on the DK (UM3300 says the DK defaults to external SMPS) TO-VERIFY[TV-12].
- [ ] Power-down order: VDDCORE/VDDA1V8 fall before VDD/VDDA1V8_AON in both the normal and the forced path (`rails.yaml` sequencing; checked by tests).
- [ ] SYS_CTX ramp (U23 CT) limits inrush into the cortex bulk caps; QOD tied to VOUT.
- [ ] Charger: BQ25798 ILIM/VSYSMIN/charge voltage straps; NTC on TS with JEITA (no charging below 0 °C: Samsung 35E charge range 0–45 °C as reference cell); BATFET and ship mode reachable; ADC left disabled in standby (TI E2E: lowest Iq with EN_ADC = 0) TO-VERIFY[TV-03].
- [ ] MAX17048: CELL to battery, VDD from battery per datasheet, ALRT open-drain into PMIC_INT_N.
- [ ] Every rail has a JP shunt footprint and a TP; JP7 rated for 2 A.

## B. ESP32-C6-MINI-1
- [ ] 3V3 pad 3 decoupling per module datasheet; EN pad 8 has RC delay and is never floating ("Do not leave the EN pin floating").
- [ ] Pad assignment matches `interfaces.yaml` (test enforces GPIO ↔ pad).
- [ ] Strapping pins: GPIO8/9 boot mode, GPIO15, GPIO4/5 (MTMS/MTDI) have the pull states we rely on TO-VERIFY[TV-15].
- [ ] Wake inputs (PIR, button, radar, PMIC_INT_N) are on LP GPIO 0–7.
- [ ] I2C_AON on LP_I2C pads (GPIO6/7), pull-ups to 3V3_AON.
- [ ] 32.768 kHz crystal decision TO-VERIFY[TV-17].
- [ ] USB D+/D− with ESD (U28) to J1; CC resistors for sink-only USB-C.
- [ ] No stock ESP-Hosted reset line from the N6 to C6 EN TO-VERIFY[TV-16].

## C. C6 ↔ N6 boundary (back-powering)
- [ ] Every signal crossing AON → CTX has a series resistor and is Hi-Z/low from the C6 side while SYS_CTX is off (firmware rule in power_tree.md).
- [ ] No pull-up on a CTX-side net goes to an AON rail (I2C_CAM pull-ups on 3V3_CTX).
- [ ] N6_PWR_ON_SENSE uses a 10 kΩ series resistor; the N6's 40 kΩ internal pull-down still defines PWR_ON.

## D. STM32N6
- [ ] Ball assignment generated by STM32CubeMX for the VFBGA-264 and copied into `interfaces.yaml` (n6 balls) TO-VERIFY[TV-14].
- [ ] XSPI1 → PSRAM (16-bit) and XSPI2 → NOR (8-bit) on the same port mapping as the DK (XSPIM_P1/XSPIM_P2), NOR reset connected.
- [ ] Boot pins and boot-from-flash configuration match the FSBL/OTA design (WS3 A/B slots).
- [ ] SWD + SWO + NRST on J3; NRST has the recommended cap.
- [ ] HSE / LSE decision (crystal or HSI only) recorded.
- [ ] DVFS GPIO defaults to 0 (0.81 V) at reset.

## E. Camera, IR, audio
- [ ] VD66GY rails 2.8 V / 1.8 V / 1.15 V and its own power-up order from its datasheet; XSHUTDOWN default low TO-VERIFY[TV-26].
- [ ] CSI-2 lane order vs N6 (lane remap allowed in software); clock lane on the clock pair.
- [ ] FFC fallback (J7) pinout matches the chosen module TO-VERIFY[TV-26].
- [ ] I2C_CAM addresses per `i2c_map.yaml` (VD66GY 0x10; IMX335 fallback 0x1A).
- [ ] IR LED constant-current sink: sense resistor sized for the LED rating; Q2 gate pull-down; IR_EN pull-down.
- [ ] IR-cut driver (U6) inputs pulled down; coil current within DRV8837 rating.
- [ ] MAX98357A: SD_MODE strap/gain resistor, supply range from SYS TO-VERIFY[TV-28]; AUDIO_EN pull-down.
- [ ] PDM mics: L/R select pins opposite, one data line, analog ground island.

## F. Sensors, security, UI
- [ ] EKMB PIR supply 2.3–4 V from 3V3_AON; output to GPIO3; account for circuit-stability time after power-up TO-VERIFY[TV-29].
- [ ] VEML7700 on I2C_AON (0x10), 2.5–3.6 V.
- [ ] ATECC608B variant ordered is MAHDA (0x60) or TNGTLS (0x35), never TFLXTLS (0x36 = MAX17048) TO-VERIFY[TV-10].
- [ ] BGT60LTR11 (DNP) footprint, supply and TD output to GPIO4 TO-VERIFY[TV-27].
- [ ] Doorbell button: ESD protection, debounce, ring-light LED current.

## G. Connectors, protection, manufacturability
- [ ] USB-C: VBUS TVS (D7) rating vs BQ25798 abs max; CC pull-downs; shield to GND through RC.
- [ ] Battery connector polarity and keyed; NTC pin to BQ25798 TS.
- [ ] Every BOM line has a fallback or "none" (`check_bom.py`), DNP flags match the build variant (radar DNP).
- [ ] Footprints checked against datasheets for U1 (VFBGA-264), U2/U3 (BGA-24), U4 (module), U12 (VQFN-HR), U15/U17 (WCSP).
- [ ] Assembly house BGA/X-ray rules and paste stencil for WCSP/BGA.
- [ ] I2C collision check passes (`python spec/i2c_check.py`).
- [ ] Power model re-run with any changed part (`make report`) and still meets G1/G2, or the deviation is written into the review.
